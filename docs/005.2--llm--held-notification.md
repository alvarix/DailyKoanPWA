# 005.2 — Show held koan text in notifications

Supersedes 005.1 Decision 1, D5, the v3 cache name in D7, and the notification checklist. The rest of 005.1 still applies. The old release needs the DB backup if rolled back after v3 migration.

The visible body in Hold is the device’s bookmarked koan text. The worker passes an empty title; iOS controls its app header and any truncation. Daily uses the server’s UTC date-hash text. Before the first online open, or if the snapshot is lost, the notification falls back to “Your koan awaits.” The sender never reads the bookmark. The worker reads the device snapshot even with the app closed. Next updates it before navigation; browsing does not change which text is saved.

## On-device acceptance (Mode 1)

After deployment, open the installed app online to activate worker v4 and populate the snapshot. Set Hold, press Next, note the text, then browse via Random and close the app. At the scheduled delivery, confirm the body is from the held koan, no custom title appears, and tapping opens the held koan. Check existing notification behavior before deploying if you want a baseline. A local commit cannot change tomorrow’s production notification until it is pushed and deployed.

Highest remaining risks are iOS worker activation and OS banner truncation. Back up SQLite before deployment; if rolling back past migration v3, restore the backup as needed for the old settings rows.
