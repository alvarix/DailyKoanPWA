# Daily Koan PWA — Migrating From the Standalone Droplet to Forge (Doc 001.11)

Version: 001.11 — llm
Status: DRAFT — not yet executed. Checkboxes for execution live in `docs/001.12--usr--migrate-to-forge-checklist.md`.

## Purpose

Move Daily Koan from the standalone droplet `dkStandalone` (Doc 001.2) onto the Forge-managed droplet `alfaForge`, configured the **same way as wmw** — a Forge site whose "Edit NGINX Settings" fragment is **body-only**, with Forge-managed SSL.

Read this first: `docs/001.1--llm--FORGE_DEPLOYMENT.md` is the postmortem of the 2026-10-24 outage. Its Section B rules are **non-negotiable** here, because this doc re-enters the shared failure domain that postmortem describes. Every nginx step below carries the gates: `nginx -t` before every reload, reload-never-restart, client-site curl 200 before and after.

```
BEFORE (Doc 001.2)                          AFTER (this doc)

dailykoan.duckdns.org                      dailykoan.duckdns.org
      |                                          |
  dkStandalone  (isolated)              alfaForge  (Forge-managed)
      nginx -> gunicorn :8001                 nginx -> gunicorn :PORT
      /opt/dailykoan                          ~/dailykoan.duckdns.org/current/
      own Let's Encrypt cert                  Forge SSL (same as wmw)
      dailykoan-push.timer RUNNING           dailykoan-push.timer (re-created)
```

The **domain never changes**. Web Push subscriptions and iOS PWA installs are bound to the origin `https://dailykoan.duckdns.org`. A domain change would silently kill every subscription and force every user to reinstall. Only the box behind the IP changes.

## Decision Gate — Should You Do This At All

| Option | Cost | Failure domain | Management |
| Stay on dkStandalone (do nothing) | $6/mo | Isolated — a mistake kills only the koan app | Manual SSH runbook (Doc 001.2) |
| Migrate to alfaForge (this doc) | $0/mo extra | **Shared** — a bad nginx fragment can take down the client site again | Unified Forge UI: SSL renewals, deploys, monitoring |

**Recommendation:** do not rush this. Migrate only after Daily Koan has been boring on the standalone droplet for a few weeks AND the reduced bill / unified management genuinely matters to you. The October outage cost 3 days of client-site downtime to save $6/mo. If you migrate, follow the gates below exactly — they are written to make the dangerous step (nginx) reversible in seconds.

## Part 2 — Pre-Stage the Forge Stack (zero public impact)

Days before cutover. Nothing here changes DNS or touches the running client/wmw sites, except A7 — the one nginx step, gated to be reversible. The goal: the entire Forge stack exists and passes local tests **before any public change**.

### P1 — Pick a free port on alfaForge

```bash
sudo ss -tlnp | grep -E ':(80[0-9][0-9]|900[0-9])'
```

Pick a port not in the list (start at 8001). Use the SAME port in A4 (gunicorn), A6 (nginx fragment), and the push units (A5). Write it down: `<PORT>`.

### P2 — Create the site in Forge UI

1. Forge → your server → **New Site**
2. Domain: `dailykoan.duckdns.org`
3. Project type: **mirror wmw** (open wmw's site page and copy its project type — flagged UNKNOWN above)
4. Web directory: whatever wmw uses (for a reverse-proxied app it is irrelevant; Forge just requires something)
5. Note the new site ID from the URL/config path (e.g. `/etc/nginx/forge-conf/<NEW_ID>/`) — this is `<NEW_ID>`, distinct from the old `3430825`

Forge will create `~/dailykoan.duckdns.org/current/` and a default nginx wrapper + fragment. This changes nothing public — the domain does not resolve here yet.

GATE P2: on the droplet, `sudo nginx -t` still passes (Forge wrote new files), and `curl -sSI https://wana....org | head -1` still returns 200. If Forge's site creation broke anything, stop and roll back (delete the site in the UI).

### P3 — Code and environment

Clone into the directory Forge created; keep the venv **outside** `current/` so Forge git deploys cannot wipe it:

```bash
cd ~/dailykoan.duckdns.org/current
git clone https://github.com/<USER>/DailyKoanPWA.git .

python3 -m venv ~/dailykoan.duckdns.org/venv
~/dailykoan.duckdns.org/venv/bin/pip install -r requirements.txt
```

Do **not** run `init_vapid.py` or `init_db.py` here — the real keys and DB migrate from the standalone droplet in Part 3 (C2).

### P4 — Gunicorn unit (Forge ignores units it did not create)

`/etc/systemd/system/dailykoan.service`:

```ini
[Unit]
Description=Daily Koan PWA
After=network.target

[Service]
User=forge
Group=forge
WorkingDirectory=/home/forge/dailykoan.duckdns.org/current
Environment="PATH=/home/forge/dailykoan.duckdns.org/venv/bin"
Environment="FLASK_HOST=127.0.0.1"
Environment="FLASK_DEBUG=0"
Environment="BASE_URL=https://dailykoan.duckdns.org/"
ExecStart=/home/forge/dailykoan.duckdns.org/venv/bin/gunicorn app:app -b 127.0.0.1:<PORT> --workers 1 --timeout 30
Restart=on-failure

[Install]
WantedBy=multi-user.target
```

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now dailykoan
curl -s http://127.0.0.1:<PORT>/api/today | head -c 120
# GATE P4: JSON returns. App runs on Forge. (No DB/subscribers yet — fine.)
```

### P5 — Push units: create now, DISABLED

Create `dailykoan-push.service` + `dailykoan-push.timer` exactly as in Doc 001.2 Phase 8, with `WorkingDirectory=/home/forge/dailykoan.duckdns.org/current`, the venv paths above, `OnCalendar=*-*-* 08:00:00`, `User=forge`.

```bash
sudo systemctl daemon-reload
# Do NOT enable the timer yet. Two enabled timers = DOUBLE PUSH at 08:00.
systemctl list-timers | grep dailykoan
# GATE P5: dailykoan-push.timer must NOT appear in the list.
```

### A7 — The nginx fragment (the dangerous step — gates first)

This is the same class of edit that caused the October outage. Follow exactly.

**7.0 Back up before touching anything** (reviewer fix — no restore path without this):

```bash
mkdir -p ~/nginx-backup
sudo cp /etc/nginx/forge-conf/<NEW_ID>/site.conf ~/nginx-backup/site.conf.pristine-$(date +%F)
# Also copy the wrapper Forge created:
sudo cp /etc/nginx/sites-available/dailykoan.duckdns.org ~/nginx-backup/wrapper.pristine-$(date +%F)
```

**7.1 Read the wrapper** (`/etc/nginx/sites-available/dailykoan.duckdns.org`) to learn the real `server_name` and include path. **Preserve every `include` directive you find there** — not just the forge-conf one.

**7.2 In the Forge UI** → site → Edit NGINX Settings, replace the fragment body with a **body-only** fragment. NO `server {`, NO `listen`, NO `server_name`, NO closing `}` — Forge provides the wrapper:

```nginx
# DailyKoan — body-only fragment (same pattern as wmw / 3081769)
# DO NOT wrap this in server{} — Forge provides the wrapper.

ssl_protocols TLSv1.2 TLSv1.3;
ssl_ciphers ECDHE-ECDSA-AES128-GCM-SHA256:ECDHE-RSA-AES128-GCM-SHA256:ECDHE-ECDSA-AES256-GCM-SHA384:ECDHE-RSA-AES256-GCM-SHA384:ECDHE-ECDSA-CHACHA20-POLY1305:ECDHE-RSA-CHACHA20-POLY1305:DHE-RSA-AES128-GCM-SHA256:DHE-RSA-AES256-GCM-SHA384;
ssl_prefer_server_ciphers off;
ssl_dhparam /etc/nginx/dhparams.pem;

add_header X-Frame-Options "SAMEORIGIN";
add_header X-XSS-Protection "1; mode=block";
add_header X-Content-Type-Options "nosniff";

index index.html index.htm;
charset utf-8;

# FORGE CONFIG (DO NOT REMOVE!) — keep ALL includes the wrapper/default carried
include forge-conf/<NEW_ID>/server/*;

location /static {
    alias /home/forge/dailykoan.duckdns.org/current/static;
    expires 30d;
    access_log off;
}

location = /manifest.json { alias /home/forge/dailykoan.duckdns.org/current/static/manifest.json; }
location = /sw.js          { alias /home/forge/dailykoan.duckdns.org/current/static/sw.js; }

location / {
    proxy_pass http://127.0.0.1:<PORT>;
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;
}

location = /favicon.ico { access_log off; log_not_found off; }
location = /favicon.svg { access_log off; log_not_found off; }
location = /robots.txt  { access_log off; log_not_found off; }

access_log off;
error_log  /var/log/nginx/<NEW_ID>-error.log error;

location ~ /\.(?!well-known).* {
    deny all;
}
```

**7.3 Validate immediately — this is the gate the October incident lacked:**

```bash
sudo nginx -t
```

- **PASS** → continue to 7.4.
- **FAIL** → restore the pristine backup in the UI (paste it back) or:

```bash
sudo cp ~/nginx-backup/site.conf.pristime-<DATE> /etc/nginx/forge-conf/<NEW_ID>/site.conf
sudo nginx -t   # must pass again
```

...then STOP and fix the fragment offline. Never reload onto an unvalidated config.

**7.4 Reload (never restart) and baseline both other sites:**

```bash
sudo systemctl reload nginx
curl -sSI https://wana....org | head -1          # GATE: still 200
curl -sSI https://<wmw-domain> | head -1         # GATE: still 200
```

**7.5 Prove the whole Forge chain works — without touching DNS:**

```bash
curl --resolve dailykoan.duckdns.org:80:<FORGE_IP> -sI http://dailykoan.duckdns.org/api/today | head -1
# GATE: 200. This forces the request to Forge while the public DNS still
# points at the standalone droplet. If this fails, fix BEFORE cutover.
```

Pre-stage is now complete. Public behavior is unchanged: DNS still routes to the standalone droplet, which serves as before.

## Part 3 — Cutover (one sitting, mid-day, away from 08:00 UTC)

Pick a time nowhere near the 08:00 push. Checklist before starting: GATEs 1.1-1.3 green, P-gates green, standalone droplet healthy.

### C1 — Disarm the standalone push timer

```bash
# on dkStandalone
sudo systemctl disable --now dailykoan-push.timer
systemctl list-timers | grep dailykoan   # GATE: empty
```

### C2 — Migrate state (three files, checksummed)

The keys and DB are the entire app state. The keys MUST match byte-for-byte: a mismatched VAPID key makes every push endpoint return 401, users' notifications silently die, and each user must re-subscribe. The snapshot uses `sqlite3 .backup` — a consistent copy even while gunicorn is writing — so the standalone site stays up through this step:

```bash
# on dkStandalone
sudo -u koan sqlite3 /opt/dailykoan/subscriptions.db ".backup '/tmp/subs-final.db'"
sha256sum /opt/dailykoan/vapid_private.pem /opt/dailykoan/vapid_public.pem /tmp/subs-final.db
scp /opt/dailykoan/vapid_private.pem /opt/dailykoan/vapid_public.pem /tmp/subs-final.db forge@<FORGE_IP>:/tmp/
```

```bash
# on alfaForge — install and verify
cp /tmp/vapid_private.pem /tmp/vapid_public.pem ~/dailykoan.duckdns.org/current/
cp /tmp/subs-final.db ~/dailykoan.duckdns.org/current/subscriptions.db
chmod 600 ~/dailykoan.duckdns.org/current/vapid_private.pem
sha256sum ~/dailykoan.duckdns.org/current/vapid_{private,public}.pem ~/dailykoan.duckdns.org/current/subscriptions.db
# GATE C2: all three hashes match the standalone side EXACTLY.
# Also record the count: sqlite3 ~/.../current/subscriptions.db 'SELECT COUNT(*) FROM subscriptions;'
```

### C3 — Restart Forge gunicorn onto the migrated state

```bash
# on alfaForge
sudo systemctl restart dailykoan
curl -s http://127.0.0.1:<PORT>/api/subscriptions/count
# GATE C3: count == standalone count recorded in C2.
```

### C4 — Flip DNS

**TTL note:** none of the usual TTL games apply — DuckDNS fixes the record TTL short (not configurable), so there is nothing to pre-lower, and the split-brain window below is minutes, not hours. Pick a cutover time away from 08:00 UTC regardless.

Now repoint the record:

```text
# DuckDNS: repoint dailykoan at the Forge droplet (web panel, or:)
curl "https://www.duckdns.org/update?domains=dailykoan&token=<DUCKDNS_TOKEN>&ip=<FORGE_IP>"
```

```bash
dig +short dailykoan.duckdns.org
# GATE C4: returns <FORGE_IP> from your resolver (other resolvers may lag briefly — DuckDNS TTL is short).
```

**Split-brain window (documented, accepted):** until every resolver expires its old cache, some users still hit the standalone droplet. It stays running and serving (C1 only disarmed its timer) — so those users see a working site whose new subscriptions land in the OLD database. The window is minutes (bounded by DuckDNS's short fixed TTL). Acceptable losses: a few subscriptions made during the window; affected users simply re-subscribe. Do NOT stop the standalone gunicorn to "fix" this — that turns lagging users' working pages into 502s, which is worse.

### C5 — SSL via Forge (immediately after C4)

Forge UI → site → **SSL → Let's Encrypt**. Let's Encrypt validates against authoritative DNS, which now points here — issuance should succeed within minutes.

```bash
# GATES after Forge finishes:
sudo nginx -t                        # Forge may have rewritten the wrapper — re-validate
sudo systemctl reload nginx
curl -sI https://dailykoan.duckdns.org/api/today | head -1     # GATE: 200
curl -sSI https://wana....org | head -1                       # GATE: still 200
curl -sSI https://<wmw-domain> | head -1                      # GATE: still 200
```

If issuance fails (propagation lag), it is low-risk: retry from the Forge UI after `dig` confirms the new IP from multiple resolvers. Users on the old IP keep a working HTTPS site the whole time; only users who already resolved to the new IP see errors until the cert lands.

### C6 — Arm the Forge push timer

```bash
# on alfaForge
sudo systemctl enable --now dailykoan-push.timer
systemctl list-timers | grep dailykoan    # GATE: timer listed, next run tomorrow 08:00 UTC
sudo systemctl start dailykoan-push.service
journalctl -u dailykoan-push.service -n 20 --no-pager
# GATE: "Sending to N subscription(s)... Done. Sent: ..." where N matches your subscriber count.
```

### C7 — Device verification

Existing iOS PWA installs keep working — the origin never changed, so no reinstall, no re-subscribe. Verify on your device:

1. Open the Home Screen icon → koan page loads (now served from Forge)
2. `curl -s https://dailykoan.duckdns.org/api/subscriptions/count` → count intact
3. C6's manual push arrives on device; tapping opens the right koan

**Standing risk, same as wmw:** Forge may re-render the fragment (PHP version change, SSL actions, template updates). ## Rollback Plan (exact commands)

Applicable any time before dkStandalone is destroyed. DNS-first, because DNS is the only public switch:

```bash
# 1. Repoint DNS (DuckDNS repoint of dailykoan — TTL short and fixed, propagates in minutes)
dailykoan.duckdns.org    A    <STANDALONE_IP>

# 2. Confirm it took effect
dig +short dailykoan.duckdns.org   # expect <STANDALONE_IP>

# 3. Disarm the Forge push timer (avoid double-push)
ssh forge@<FORGE_IP> 'sudo systemctl disable --now dailykoan-push.timer'

# 4. (If rolling back after users subscribed on Forge) copy the DB back:
#    on alfaForge: sqlite3 ~/dailykoan.duckdns.org/current/subscriptions.db #      ".backup '/tmp/subs-rollback.db'"
#    scp it to dkStandalone /opt/dailykoan/subscriptions.db (checksum both sides)
#    VAPID keys are identical everywhere — nothing to re-key.

# 5. Standalone serves immediately: its gunicorn never stopped, certs still valid.
curl -sI https://dailykoan.duckdns.org/api/today | head -1   # GATE: 200
```

Nginx on Forge needs no rollback in this scenario — leaving the (validated) Forge fragment in place is harmless once DNS points elsewhere. If instead you must roll back a BROKEN nginx state on Forge, use the 7.3 restore path (`cp ~/nginx-backup/site.conf.pristine-<DATE>` back, `nginx -t`, reload) — that is why 7.0 exists.

## For Dummies (Plain English)

We built the koan app on its own small server so that our mistakes could only hurt the koan app. Now that it has been boring for weeks, this doc moves it onto the big server — the one Forge manages, the same way your wmw site works. The move is like moving house without changing your mailing address: the web address (`dailykoan.duckdns.org`) stays identical, so nobody's phone has to re-install anything. The two keys that make notifications work, and the little list of who wants notifications, get copied over first — with fingerprints checked, like counting the silverware — before we flip the signpost (DNS) that says which house visitors should knock at. The dangerous part is the nginx settings inside Forge, because that is exactly where last October's disaster started; so we save a photocopy of everything BEFORE we touch it, and we run the "does the config parse" check after every single change. Your client's website gets a health check before and after every step. If anything goes wrong, we flip the signpost back, and the old house — still fully furnished — answers the door again within five minutes.
