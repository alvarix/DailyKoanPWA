## Plain English — what this is

The koan pushes went silent on Nov 18 and 19. Nothing was broken: held mode as shipped in 0.1.6 only pushed when someone pressed Next and moved the shared pointer. Nobody pressed, so every 08:00 UTC run exited quietly — by design. Alvar's Nov 19 decision supersedes that design: **"in held mode I should still receive the notification — the same koan until I advance, every day."**

So the cadence was rebuilt as *data*: the server timer now ticks every hour, and the drawer's `push_time` + `push_timezone` (05:00, America/New_York) decide which tick delivers. Both modes now deliver exactly once per local day; held mode re-announces the current koan daily until Next advances it.

## The missed push — evidence and closure

Root cause confirmed from the droplet journal + settings rows, not guessed:

- Timer healthy: fired 08:00 UTC every day, including Nov 19 (before the fix deployed).
- Nov 17 08:00:41 — push sent ("Chao-chou in the Snow, index 11, mode=held", `Sent: 1`) — 0.1.6 held mode with a fresh pointer.
- Nov 18 + 19 08:00 — "Nothing new to push (mode=held, current_index=11, last_push_index=11)" — quiet exits, exactly as coded: the pointer had not moved since Nov 17.
- The Nov 15 `403 BadJwtToken` + "Removed dead subscription" lines are pre-0.1.5 code (the incident that cost a subscription) — historical journal, not current behavior.

Nothing in the old code needed fixing. The spec changed.

## What shipped in 0.1.8

56/56 tests green locally (`venv/bin/python -m unittest discover -s tests`; up from 47).

- **Cadence is settings data.** New `push_timezone` row (default `America/New_York`), `SETTINGS_VERSION = 2`, additive insert-or-ignore migration — existing values preserved; the droplet upgraded on first app start after deploy.
- **The decision, made fresh every hourly run** (`koan_selector.select_push`): delivery gate (`is_delivery_time` — local time ≥ `push_time`, DST-correct via `zoneinfo`; garbage time/zone falls back to 08:00 / UTC) → local-day dedupe (`last_push_date` now stores the *local* delivery date) → mode branch (daily: UTC date-hash koan, unchanged site parity; held: re-announce `current_index` daily). `last_push_index` no longer suppresses sends.
- **Every exit is journaled.** `push_sender.py` states why it exits: "Before the delivery moment…", "Already delivered today — dedupe (…)", or the send-loop summary. The silence that hid Nov 18–19 cannot recur.
- **The drawer owns the schedule.** Timezone display (Alpine-bound, updates live), auto-sync from the device on load (`Intl.DateTimeFormat().resolvedOptions().timeZone`, silent when unchanged), plus a manual "Use my device timezone" tap with a toast. `POST /api/settings` accepts `push_timezone` (must be a loadable IANA zone).
- Tests added: delivery-gate suite (open/close boundary, UTC→EST conversion, garbage fallbacks for time and zone), held re-announce, per-local-day dedupe in both modes, timezone API round-trip + 400s.

## Decisions recorded (2026-11-19)

- Held mode re-announces the current koan daily until Next advances it ("the same koan until I advance, every day") — supersedes 002 tweak 1's push-only-on-pointer-move behavior.
- Delivery at 05:00 US Eastern, auto-detected from the device, overridable in settings ("i am est. if not auto-detected it should be in settings").
- The hourly timer is the mechanism; the unit-file edit was the last timer ops step. Cadence changes are drawer-only from here.
- 002's open decision "held-mode push latency up to ~24h" is superseded: latency is ≤ 1h after the daily moment, DST-correct.

## For dummies

The app used to have one alarm: 08:00 UTC (3am New York). Now it checks the clock every hour, and hands you the koan only when your local clock passes 05:00 New York — once a day, every day, the same koan until you tap Next. The drawer's timezone row is how the server learns your clock.
