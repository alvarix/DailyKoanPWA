## Plain English

Today "Next Koan" moves one shared bookmark for the whole internet, and anyone who opens the public URL can move it. After this spec: Next moves only YOUR reading position, saved on your device. The server stops storing any "current koan". The morning push stops following anyone's pointer — it always delivers today's date-hash koan (Open Decision 1 below). Nobody can change your koan because nothing shared is left to change.

The daily/held distinction survives as a per-device preference: daily = "rotate with the date" (server-rendered date-hash, stateless), held = "stay on my koan" (your device's position).

## Design

### D1. Client-local state — localStorage

| Key | Values | Meaning |
| --- | --- | --- |
| `dk-mode` | `held` \| `daily` | per-device mode (default seeded, see D4) |
| `dk-index` | int | held reading position |
| `dk-progression` | `ordered` \| `random` | how Next jumps |

All localStorage access wrapped in try/catch with default fallbacks (private mode / quota errors must never break the page). `dk-index` clamped `mod total` on every read (corpus growth/shrink can never produce an out-of-range position).

### D2. Site rendering — stateless server

- `GET /` renders **today's date-hash koan** (UTC date hash, unchanged formula) for every visitor. No server mode read — there is no server mode.
- Held devices: on load, JS `location.replace('/koan/<dk-index>')` — one extra round trip; brief first-paint flash of today's koan (accepted; D6 covers the failure fallback). Daily devices: no redirect, stay on `/`.
- **Next (held):** compute next (`ordered` = +1 mod total, `random` = a different index), persist `dk-index`, `location.assign('/koan/<next>')` — a plain navigation the server renders. No API write, no client-side rendering framework.
- **Next (daily):** unchanged per-visitor link `/koan/<idx+1>` — daily browsing stays browsing.
- Deep links `/koan/<idx>`: unchanged, per-visitor, never touch `dk-index`.
- Drawer Hold/Daily + In order/Random buttons: flip localStorage, `location.reload()` — instant, **no server posts**.

### D3. Server removals

- `POST /api/next` → deleted, returns **410 Gone** (explicit: distinguishes a removed route from a typo).
- `POST /api/mode` → deleted, 410.
- Settings rows `mode`, `progression`, `last_push_index` → dropped. `current_index` → kept as **read-only legacy seed** for D4; never written again; dropped in a later cleanup once Alvar's device has seeded (D4 records the window).
- `SETTINGS_VERSION = 3` migration: one transaction (`BEGIN IMMEDIATE`), `DELETE ... WHERE key IN (...)`, version bump last — idempotent, safe for app-startup and push-run concurrency (both run it; `INSERT OR IGNORE` semantics elsewhere unchanged).
- `koan_selector.advance()` → deleted. `set_values` → `push_time`/`push_timezone` only. `VALID_MODES`/`VALID_PROGRESSIONS` → deleted.
- `push_time`/`push_timezone` stay server-side settings (they are **delivery** config, not content).

### D4. One-time seed (migration window)

- Template context gains `held_seed` = the old `current_index` row value.
- JS on load: **only if `dk-index` is absent** → `dk-index = held_seed`, `dk-mode = 'held'`. Alvar's device keeps its position (11 as of Nov 20, wherever the taps left it). Present `dk-index` → seed ignored, forever.
- New devices later also seed held+seed — N=1 accepted tradeoff (recorded, not silent): the seed row is dropped in a future cleanup, after which fresh devices default `daily`. There is no client-side way to distinguish "Alvar's device that used to sync" from "a brand-new device" — both have empty localStorage.

### D5. Push — stateless (Open Decision 1 default)

- `select_push` becomes: delivery gate (`push_time`/`push_timezone`, unchanged) → per-local-day dedupe (`last_push_date`, unchanged) → **today's date-hash koan**. No mode branch, no pointer read, `last_push_index` never consulted.
- Payload unchanged (0.2.0): `title` = koan title, `body` = koan text, `data.url` = deep link. Tapping the notification opens the pushed koan.
- Pre-existing accepted property (unchanged): site date-hash uses the UTC date, dedupe uses the `push_timezone` local day — can straddle midnight; cosmetic at worst.

### D6. Failure modes

- `dk-index` out of range after corpus change → clamped `mod total` before redirect (D1).
- `/koan/<dk-index>` 404s (mid-deploy, corpus shrink) → JS resets `dk-index` to the seed (or 0), toasts, stays on today's koan.
- Redirect/seed logic throws → server-rendered today-koan page remains fully functional (held is progressive enhancement, not a dependency).

### D7. Service worker

- `CACHE_NAME` `daily-koan-v2` → `daily-koan-v3` (template changed). Navigation is already network-first, so stale shells self-heal on first online load.

## Open decisions (Alvar — answer in chat before implementation)

1. **Push body in held mode — the central one.** The stateless push delivers *today's* koan, which **contradicts your 0.1.8 request** ("the same koan until I advance, every day"). Two honest options:
   - **A (this spec's default): stateless daily push.** The notification is the daily koan delivery — the app's stated purpose; held mode becomes your private reading position. Cost: in held mode the pushed koan ≠ your held koan; the mismatch is visible.
   - **C (documented fallback, NOT implemented here): token-gated server pointer kept as push source.** Preserves 0.1.8's literal semantics. Cost: a settings row (`operator_token`) + a token header on the one write endpoint — i.e. shared-secret auth, the class 005 §4 rejected, now justified by an explicit user request. Site goes client-local either way.
2. New-device default after the seed cleanup: `daily` (recommended).
3. Timing: implement before or after tomorrow's 05:00 re-add verification (deploy window is one either way).

## Rejected alternatives (recorded)

- **Shared secret on `/api/next` keeping global sync** (005 §4): patches the symptom, keeps the unrequested sync.
- **Per-visitor server state keyed to the subscription** (005 peer review): the subscription↔visitor link is fragile across reinstall/new-phone — this very incident's failure mode.
- **Generic push body** ("a koan awaits"): loses the koan-in-notification, 002 tweak 2's whole point.
- **Alpine fetch-and-render client rendering** (GPT reviewer): plain navigation to existing server routes needs no new rendering path; zero-build stays zero-build.

## Tests (Mode 2, local)

Python suite:
- Stateless `select_push`: gate/dedupe/date-hash; no pointer read; `last_push_index` absent → no crash.
- Migration v3: idempotent double-run; drops `mode`/`progression`/`last_push_index`; preserves `current_index` seed, `push_time`, `push_timezone`, `last_push_date`, subscriptions.
- `/api/next` + `/api/mode` → 410; settings POST with `mode`/`progression` → 400.
- Template: carries `held_seed`, zero `/api/next` and `/api/mode` references; SW `CACHE_NAME` v3.

No JS test framework (zero-build repo) — client logic covered by template assertions + the on-phone checklist below.

## Deploy + verification (Mode 1)

Runbook 9.2: db backup (`.backup`) → pull → restart → timer re-arms hourly. Migration runs at startup.

Rollback: redeploy prior commit; restore db backup only if needed (old code tolerates a v3 DB via `INSERT OR IGNORE`; version downgrade is inert).

On-phone checklist:
1. Open app → brief today-koan flash → lands on held koan (position kept).
2. Next → advances locally; persists after force-close.
3. Drawer Hold/Daily toggle → instant, network tab idle (no server posts).
4. Tomorrow 05:00 → push arrives; title line = koan title; body = full koan.

## For dummies

"Next" used to move one shared page-marker that the whole world shared. Now the marker lives on your phone, and the website just shows today's page to whoever asks. The morning notification is like a page-a-day calendar again — it can't be pushed off course by a stranger, because it doesn't track anyone's bookmark.
